# Research and art-stage handoff

The primary live tinygyn view, tiny.london, its how-it-was-made article, and isometric.nyc were inspected in Chrome. Research screenshots are in ignored `data/references/screenshots/`; these are not production assets or training examples. The linked X video returned 403 and was not watched. Exact upstream revisions, inspected files and license findings are in [REFERENCES.md](REFERENCES.md) and [source-revisions.json](source-revisions.json). No upstream source or imagery was copied into the app.

Code/data/model licenses remain separate. isometric-nyc and iso-cities have actual MIT files. Cityscope's README/package says MIT but its tree has no license file; sf-isometric-demo has none; MultiDiffusion has no root license, although its ControlNet file carries an Apache-2.0 header. These projects informed concepts only. Keep OSM attribution with both the viewer and exported artwork; see [PROVENANCE.md](PROVENANCE.md).

Hawa Mahal's five-tier street facade, City Palace's separate courtyard structures, and Jantar Mantar's astronomical instruments are supported by the sources cited in REFERENCES. The original landmark meshes are artistic reconstructions located using OSM geometry/POIs. Dimensions, decoration and heights inferred by the renderer must not be described as surveyed. Samrat Yantra's gnomon follows true north–south and rises northward near 27°; the cited specialist modelling source gives approximately 22.6 m for the gnomon itself.

`outputs/doctor.json` records Apple M3, 8 GiB unified memory, 10 GPU cores, Metal support, Python 3.9.6, Node 18.20.4 and about 97 GiB free at the latest measurement. An existing Node 22.13.0 executable was used for the initial reference browser capture. No CUDA was installed. PyTorch/MPS could not be tested because PyTorch is absent.

`outputs/art-preflight.json` explicitly records **mode B blocked / generated_art=false**. The inspected Apache-declared original Qwen checkpoint is about 53.76 GiB in total; its BF16 transformer alone exceeds 38 GiB. It cannot fit within this machine's 8 GiB physical memory. No weight, LoRA or adapter was downloaded or trained. The preflight and safe refusal are hardware-tested; actual image-edit execution is untested. `npm run stylize-pilot` returns 2 for missing requirements; add `-- --check` for a report with exit 0. Its default input is `outputs/render/pilot.png`.

Four art preflight tests passed with `python3 -m unittest discover -s tools/stylize -p 'test_*.py' -v`: unconfigured refusal; parameter-memory floor even for incomplete tiny weights; rejection of unreviewed revision or oversized crop/steps/time; and `--execute` producing no artwork when the model is missing. The optional future provider is single-crop only, uses local files, checks memory before loading and RSS between denoising steps, and has a time alarm. These checks are not a hard OS memory cap. Joint-window denoising and polished city art remain unfinished; full next steps are in [ART-STAGE.md](ART-STAGE.md).

Final geometry/render and viewer QA are documented by their own generated reports. Do not substitute reference-site visual quality or published cloud inference timings for measurements of this pilot. The 6144 × 5120 deterministic target remains mode A, regardless of its crisp pixels or selected palette.
